# ProofPath AI: The Evidence Detective

**Tags:** `#strands-decider-2b` `#tool-selection`

## The problem

AI performance claims are easy to publish and surprisingly hard to verify.
“Our model reaches 98% accuracy” can hide class imbalance, test-set tuning,
train/test leakage, a tiny test set, or a number that does not match the
released predictions.

ProofPath AI is an explainable evidence-gathering agent. It investigates a
claim one check at a time and produces a verdict backed by visible,
reproducible findings:

- supported
- contradicted
- insufficient evidence

## The agent

The agent reads prediction and training CSVs plus evaluation notes or a paper
excerpt. Its deterministic tools recompute accuracy, compare against a
majority-class baseline, calculate a Wilson confidence interval, inspect
per-class recall, detect train/test overlap, scan evaluation notes for test
set tuning, and cross-check the paper.

The final verdict is never generated by a language model. Every measurement
comes from Python, and missing artifacts are reported as unverified instead of
being silently ignored.

## The Decider 2B decision

This project demonstrates the **tool-selection** decision pattern.

At each step, Strands Decider 2B receives:

1. the claim and its available artifacts;
2. the findings already collected; and
3. a closed list of evidence tools that are still available.

It answers the typed question:

> Which evidence check should run next?

The returned choice must match one of the available tool names. The agent then
executes that deterministic tool. Decider 2B decides *where to look next*,
not whether the claim is true.

This is a meaningful repeated decision: after every finding, the best next
check can change. For a high-accuracy claim with training data available,
leakage may be more valuable than another generic check. For a small test set,
uncertainty becomes the priority. The decision pattern is reusable in any
agent that routes a request through a bounded set of tools.

## Amazon Bedrock pairing

Amazon Bedrock Nova provides the generative explanation path. The UI can show
a concise explanation of why the selected check matters, while Decider 2B
handles the fast closed-set routing decision. This hybrid design keeps the
expensive generative model out of the frequent routing path and keeps
measurements auditable.

If either service is unavailable, the application explicitly reports the
fallback and continues with a local policy. That makes the demo reliable
offline without changing the evidence or verdict semantics.

## What the demo shows

The Streamlit UI shows the selected tool, the reason it was selected, the
finding, the verdict, the number of checks run, and evidence coverage. On the
seeded benchmark, the adaptive policy finds planted flaws faster than a fixed
checklist while maintaining the expected verdicts.

## What I learned

Large language models are useful for explanation, but they are unnecessary
for every small decision in an agent loop. A calibrated, focused decision
model is a strong fit for repeated routing over a short option set. Separating
routing, measurement, and explanation also makes the system easier to test and
trust.

ProofPath AI is an original hackathon project built for experimentation with
Strands Decider 2B and Amazon Bedrock.
